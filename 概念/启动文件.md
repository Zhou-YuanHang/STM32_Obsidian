# STM 32 启动文件（.s 文件）详解

> 启动文件是**汇编语言写的文件**，后缀 `.s`，STM 32 工程里常见：`startup_stm32f10x_hd.s` 这类。 很多人误以为 `main()` 是程序入口，**不是！** CPU 上电最先跑的是启动文件，跑完才跳转到 `main`。

## 启动文件核心作用一句话
上电/复位后，先设置栈、堆，建立中断向量表，初始化系统最底层环境，最后调用 `main()`；并且定义好各个中断服务函数的入口。

---

## 一、上电复位完整执行流程（启动文件干的事）

1. **复位（Reset）触发** MCU 上电、硬件复位，CPU 会去固定地址读取两个值： 
	- **0x08000000**：存放 MSP（栈顶指针）
	- **0x08000004**：存放 Reset_Handler（复位函数入口地址）

2. **复位程序 `Reset_Handler`（启动文件核心函数）**
```
Reset_Handler PROC
    IMPORT __main
    LDR R0, =__main
    BX R0
ENDP
```

`__main` 不是你写的 `main`，是编译器库函数，它做两件大事：

- 拷贝 **RW 段**：已经初始化的全局变量，从 Flash 复制到 RAM
- 清零 **ZI 段**：未初始化全局变量，在 RAM 全部置 0 完成之后，才会调用你写的 C 语言 `main()`

> 段的简单理解：
> 
> - RO：只读，代码+常量，存 Flash
> - RW：已初始化全局变量，Flash 存初始值，运行时拷贝到 RAM
> - ZI：零初始化变量（全局 int a;），RAM 区域清零

3. **定义栈（Stack）和堆（Heap）** 启动文件开头有这两个宏：

```
Stack EQU 0x400   ;栈大小，局部变量、函数调用、中断现场用
Heap  EQU 0x200   ;堆大小，malloc动态内存用
```

- **栈 Stack**：向下生长。保存函数局部变量、函数返回地址、中断压栈。栈溢出程序会跑飞。
- **堆 Heap**：向上生长。给 `malloc / free` 使用；嵌入式开发很多时候不用堆，可以改小甚至设 0。

4. **中断向量表（最重要）** 向量表本质是一张**函数指针数组**，存各个中断服务函数的入口地址，放在 Flash 起始位置。

```
DCD     Reset_Handler             ;复位入口
DCD     NMI_Handler                ;NMI异常
DCD     HardFault_Handler          ;硬件错误
DCD     MemManage_Handler
...
DCD     WWDG_IRQHandler            ;窗口看门狗中断
DCD     USART1_IRQHandler          ;串口1中断
```

规则：

- 向量表里面所有中断函数，**默认都是弱定义（WEAK）**

```
WEAK USART1_IRQHandler
B USART1_IRQHandler  ;原地死循环
```

意思：如果你在 C 文件里写了 `USART1_IRQHandler()`，编译器会优先用你写的函数；**如果你没写，触发中断就会进入这个死循环，程序卡住**。

> 弱符号 `WEAK` 是启动文件非常关键的特性。

5. 跳转进入 `main()`，交给 C 代码运行。

## 二、启动文件里几个关键概念区分

1. 启动文件和系统时钟 `SystemInit()` 的关系
    
    > ST 标准库：`Reset_Handler` → `__main` 之前会调用 `SystemInit()`，用来配置系统时钟。 注意：HAL 库有些版本 `SystemInit` 放到 `main` 开头调用，这点标准库和 HAL 库有差异。
    
2. 启动文件是汇编，我们一般**不修改** 日常开发几乎不用改 `.s`，只有少数场景需要改动：

- 需要调整栈、堆大小（任务栈不够、malloc 要更大堆）
- 自定义向量表（比如使用中断重定向、RTOS）
